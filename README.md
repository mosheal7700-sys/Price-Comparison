# הסל הזול

אתר להשוואת מחירי סל קניות בין רשתות וסניפים, לפי עיר. האתר רץ ב-GitHub Pages והמחירים מתעדכנים אוטומטית.

## איך זה עובד

1. **GitHub Actions** מריץ את `collect.py` בערך כל שעתיים (10 תזמונים עם בדיקת מרווח, ראה בהמשך), ובלחיצה ידנית. בפועל GitHub מדלג על חלק מההפעלות המתוזמנות, והתזמונים הנוספים מכסים על כך.
2. הסקריפט מוריד מכל רשת את קבצי המחירים שהיא מחויבת לפרסם לפי חוק שקיפות מחירים (באמצעות הספרייה [israeli-prices](https://pypi.org/project/israeli-prices/)), מתאים מוצרים לפי ברקוד וכותב קובצי JSON לכל עיר.
3. אותו תהליך מפרסם את `index.html` יחד עם תיקיית `data/` ל-GitHub Pages.
4. בכל פתיחה של האתר, הדפדפן טוען את קובצי ה-JSON האחרונים. הכפתור "רענן מחירים" טוען אותם שוב.

אין באתר נתוני דוגמה. אם הקבצים לא קיימים או לא נטענו (למשל כשהאתר נפתח ישירות מהמחשב, או שההרצה לא פורסמה), האתר מציג הודעה שמסבירה מה נכשל ומה לבדוק.

## התקנה

1. העלה למאגר, בשורש: `index.html`, `collect.py`, `config.json`, `requirements.txt`, `README.md`.
2. צור את הקובץ `.github/workflows/update.yml`: Add file ← Create new file, הקלד את הנתיב המלא בשם הקובץ והדבק את התוכן.
3. Settings ← Pages ← Build and deployment ← Source: **GitHub Actions**.
4. לשונית Actions ← "עדכון מחירים ופרסום האתר" ← Run workflow.
5. אחרי כמה דקות האתר מתעדכן. כדי לראות מה נאסף, פתח `<כתובת האתר>/data/index.json`: השדה `chains` מראה מה מצב כל רשת.

## שימוש באתר

- **חיפוש:** כל מילה שמקלידים חייבת להופיע בשם המוצר, בכל סדר ובכל מקום ("טחון בשר" ו"בשר טחון" נותנים אותו דבר). מוצגות עד 100 תוצאות. ליד כל אחת המחיר הזול ביותר בעיר, ומתחת לשם רשימת הרשתות שמחזיקות אותה (הזולה ביותר מודגשת).
- **בחירה מרובה:** מסמנים כמה מוצרים בתיבות הסימון ולוחצים "הוסף נבחרים להשוואה" (או Enter). תיבת הסימון גדולה, ובזמן שיש סימון, לחיצה בכל מקום בשורה מסמנת אותה ולא מוסיפה אותה לבד, כדי שלחיצה שפספסה את התיבה לא תאבד את הבחירה. הם נכנסים לטבלה כקבוצת השוואה: בכל חנות נספר בסכום רק המוצר הזול ביותר בקבוצה, והמספר האדום מראה כמה תוסיף אם תבחר במוצר אחר. "השאר" משאיר מוצר אחד.
- **איחוד שורות:** סמן בתיבות הסימון שליד שמות המוצרים בטבלה שתי שורות או יותר (למשל כמה שורות "עגבניה" שנוספו בנפרד) ולחץ "אחד לשורה אחת". השורה הממוזגת מראה בכל חנות את הגרסה הזולה ביותר שהיא מחזיקה, והסל נספר כמוצר אחד. "הצג" פותח את הגרסאות ו"השאר" משאיר אחת, "פרק" מחזיר לשורות נפרדות. האיחוד נשמר בדפדפן.
- **פריט שנעלם מהנתונים:** אם מוצר שבסל לא נמצא בנתונים אחרי עדכון (למשל כשהמזהה שלו השתנה), הוא לא נמחק בשקט. האתר מנסה למצוא אותו לפי שם וגודל זהים, ואם לא נמצא, מוצגת הודעה עם שמו ולחצן "הסר". הוא חוזר לטבלה לבד כשהוא מופיע שוב.
- **תיאור הגרסה ובחירה ידנית בשורה ממוזגת:** מתחת למחיר בשורה הממוזגת מופיע, בפונט קטן, תיאור הגרסה המקורית שנספרת באותה חנות. "הצג" פותח את הגרסאות, ולחיצה על המחיר של גרסה בחנות מסוימת בוחרת אותה לחנות הזו בלבד, גם אם היא יקרה יותר (מסומן "נבחר ידנית"). לחיצה נוספת מחזירה לבחירה האוטומטית, הזולה ביותר. הבחירה נשמרת בדפדפן.
- **העברת סל בין מכשירים:** הכפתור "העבר סל" הוסר. הסל עובר בקובץ הרשימה: "שלח / הדפס רשימה" ← "שלח בוואטסאפ" (או "שמור כקובץ"), והקובץ כולל כפתור "פתח באתר" עם קישור הסל המלא (העיר, איחודי השורות, הכותרות והבחירות הידניות). פתיחת הקישור במכשיר אחר טוענת את הסל, ואם כבר יש שם סל האתר שואל אם להחליף, להוסיף או להתעלם. הנתונים נדחסים בקישור (כ-8–9 תווים לפריט), נשמרים רק בקישור ובדפדפן ולא בשרת, והקישור הוא תצלום של הסל ברגע היצירה, לא סנכרון חי. קישורים שנוצרו בעבר ממשיכים לעבוד.
- **שינוי סדר שורות:** ליד כל שורה בטבלה יש חיצי העלאה והורדה (⌃ ⌄) כדי לסדר את הסל לפי נושאים. שורה מאוחדת זזה כיחידה אחת עם כל הגרסאות שלה, ושורות המשנה נשארות צמודות אליה. הסדר נשמר בדפדפן ועובר גם בקישור "העבר סל". החצים מוסתרים כשיש פחות משתי שורות.
- **סידור שורות מסומנות:** בסרגל שמופיע כשמסמנים שורות יש "סדר קבוצה" (מרכז את המסומנות ברצף, אחת אחרי השנייה, בלי לאחד אותן), "למעלה" ו"למטה" (הזזת כל המסומנות בצעד אחד, כקבוצה), "לראש" ו"לסוף". שורות מוסתרות לגמרי מדולגות.
- **הסתרה מהסיכום:** מסמנים שורה אחת או יותר בתיבת הסימון ולוחצים "הסתר מהסיכום". השורה נשארת בטבלה בעמעום, אך אינה נספרת בסכומים, בסל הזול ובקנייה המפוצלת. "החזר לסיכום" או "החזר הכל" מחזירים. ההסתרה נשמרת בדפדפן. הטבלה רחבה יותר במסכים גדולים (עד 1560 פיקסלים).
- **החבאה מלאה והדפסה:** כשיש שורות מוסתרות, בתיבת הסיכום מופיע "החבא לגמרי" שמעלים אותן מהטבלה לגמרי (ו"הצג מוסתרות" מחזיר אותן, עם העמעום). הכפתור "שלח / הדפס רשימה" מאפשר לבחור חנות ולהדפיס (או לשמור כקובץ HTML ולהדפיס אחר כך) את השורות הפעילות בלבד, עם הגרסה והמחיר שנספרים באותה חנות, תיבת סימון לכל פריט וסה״כ. ניתן להדפיס בלי מחירים.
- **כמות:** עמודת "כמות" בין המוצר לרשתות (ברירת מחדל 1, אפשר גם עשרוני כמו 2.5). המחירים בטבלה, הסכומים, הסל הזול והקנייה המפוצלת מחושבים לפי הכמות, ומתחת למחיר מוצג המחיר ליחידה. הכמות מופיעה גם ברשימת ההדפסה / קובץ ה-HTML. הכמות והשורות המוסתרות עוברות גם בקישור "העבר סל".
- **כותרות נושא:** הכפתור "הוסף כותרת" מוסיף שורת כותרת (למשל "מוצרי חלב", "ירקות") בסוף הטבלה, או מעל השורה המסומנת הראשונה. הטקסט נערך ישירות בשורה. אפשר להזיז כותרת עם החיצים או כחלק מ"סדר קבוצה" כמו כל שורה, ולהסיר אותה ב-X. הכותרות עוברות בקישור "העבר סל", ונכנסות לרשימת ההדפסה ולקובץ ה-HTML כשורת מפריד. כותרת שלא נמצאות אחריה שורות פעילות לא מודפסת. הכותרות אינן משפיעות על הסכומים.
- **שמור לסימניות:** דפדפן לא מאפשר לאתר ליצור סימנייה בעצמו, ולכן הכפתור מעדכן את כתובת הדף כך שתכיל את הסל (כמו קישור "העבר סל"), ומציג הודעה עם הקיצור לשמירה (Ctrl+D, בטלפון: תפריט הדפדפן ← הוסף סימנייה). פתיחת הסימנייה טוענת את הסל, ושואלת אם להחליף את הסל הקיים.
- **סניף שלא ירד נשאר בעמודה (נתונים ישנים):** כשהורדת קובץ של סניף נכשלת, הסניף מוצג מהפעלה הקודמת עם התווית "נתונים ישנים". זה חל על כל סניף שהוצג קודם, גם סניף נוסף מ-`extra_branches`, כך שרשת עם שתי עמודות לא יורדת בשקט לעמודה אחת. בלוג מופיעה שורה `[stale]` וליד כל כשל שורת `[prices] … FAILED` עם הסיבה.
- **רשימה כללית לרשת כשרשימת הסניף חסרה:** כשהפורטל עונה "no PriceFull file for store N" לסניף (למשל באושר עד, כשרוב הסניפים נכשלים), הרשת נרשמת פעם אחת בבקשה אחת, והסניפים מחופשים בה. בלוג שורות `[listing]` מראות כמה קבצים הפורטל מציג, מה נמצא, ואם הסניף באמת חסר, אילו קבצים הפורטל מציג לו.
- **חיפוש לפי ברקוד:** בשדה החיפוש אפשר להקליד ברקוד (4 ספרות ומעלה, כולל חלק ממנו): הפריטים שהברקוד שלהם מתאים מופיעים קודם, והברקוד מוצג בשורת התוצאה. חיפוש לפי שם עובד כרגיל. פריט שכבר בסל לא מופיע שוב בתוצאות. כשהחיפוש לא מוצא שום תוצאה אבל יש בסל פריטים שמתאימים לו, מופיעה שורה "כבר בסל (N): …" עם שמותיהם (גם כשהם בקבוצה מכווצת או מוסתרים). כשיש תוצאות אחרות השורה לא מוצגת.
- **כיווץ קבוצה תחת כותרת:** בכל שורת כותרת נושא יש כפתור ▾/◂ שמכווץ את הפריטים שמתחתיה (עד הכותרת הבאה). בכותרת מכווצת מופיעה תווית "N פריטים מוסתרים". הפריטים המכווצים נשארים בסל ובסיכום, רק לא מוצגים, כדי להקל על הוספה וסידור בקבוצה אחת ברשימה גדולה. בכותרת העמודה "מוצר" יש גם "כווץ קבוצות" ו"פתח קבוצות". המצב נשמר בדפדפן ולא עובר בקישור.
- **הוספה לקבוצה נבחרת:** בכל כותרת כפתור "+ הוסף לכאן". לחיצה הופכת את הקבוצה ליעד (הכותרת מודגשת ומעל החיפוש מופיע "מוסיף אל: …"), וכל פריט שנוסף מהחיפוש (גם כמה יחד או קבוצה ממוזגת) נכנס בסוף הקבוצה, לפני הכותרת הבאה, גם אם היא מכווצת. היעד נשאר פעיל עד לביטול (✕ או לחיצה חוזרת) או בחירת קבוצה אחרת, ואינו נשמר ברענון. כותרת שנוספה זה עתה הופכת ליעד אוטומטית. כשאין יעד, פריט חדש נכנס לאזור שלפני הכותרת הראשונה (בלי קבוצה), ולא לקבוצה האחרונה; כשאין כותרות הוא נוסף בסוף הרשימה כרגיל.
- **העברת שורות מסומנות לקבוצה:** כשמסמנים שורות ויש בסל כותרות, בשורת הכפתורים מופיעה רשימה "העבר לקבוצה…". בחירת כותרת מעבירה את השורות המסומנות (מכל קבוצה, כולל ממוזגות) לסוף הקבוצה הזו, לפי הסדר שבו הן מופיעות. "בלי קבוצה" מוציא אותן מכל קבוצה, לאזור שלפני הכותרת הראשונה. אם הקבוצה היעד מכווצת, הסימון מתבטל והיא נשארת מכווצת. לשינוי מיקום בתוך קבוצה אפשר להמשיך להשתמש בחצים ובכפתורים "לראש"/"לסוף".
- **הסתר הכל / החזר הכל:** בכותרת העמודה "מוצר" שני כפתורים קטנים. "הסתר הכל" מוריד את כל הרשימה מהסיכום בלחיצה אחת, ואז אפשר לסמן כמה שורות ולהחזיר רק אותן ("החזר לסיכום"). "החזר הכל" מחזיר את כל הרשימה לסיכום. מתאים לקנייה חלקית קטנה מתוך רשימה גדולה.
- **שיתוף בוואטסאפ:** בחלון "שלח / הדפס רשימה" הכפתור "שלח בוואטסאפ" שולח את קובץ ה-HTML עם הסימון ✓ (אותו קובץ של "שמור כקובץ"). בטלפון ובדפדפנים שתומכים בשיתוף קבצים נפתח חלון השיתוף: בוחרים וואטסאפ ונמען ושולחים. כשהדפדפן לא תומך (בדרך כלל במחשב) הקובץ נשמר ווואטסאפ נפתח, ומצרפים אותו בסיכה. קובץ ה-HTML (גם ב"שמור כקובץ") כולל כפתור "פתח באתר (להשוואת מחירים ועריכה)" עם קישור הסל המלא בתוכו, ולכן סל גדול שהקישור שלו ארוך מדי להודעת וואטסאפ עובר בקובץ, ובטלפון לוחצים ופותחים אותו באתר.
- **סימון ביצוע בטלפון:** בקובץ ה-HTML שנשמר, לחיצה על שורה מסמנת אותה (קו חוצה וסימון ✓), ויש מונה "סומנו X מתוך Y" וכפתור "נקה סימונים". הסימונים נשמרים בדפדפן שפתח את הקובץ, ולא מופיעים בהדפסה. בדפדפנים שחוסמים הרצת קוד מקבצים (למשל תצוגה מקדימה בחלק מאפליקציות הקבצים) הקובץ יוצג בלי יכולת סימון.
- **ניקוי פריטים שלא בשימוש:** כשיש בסל שורות ממוזגות עם פריטים שאינם הזולים באף חנות ולא נבחרו ידנית, מופיע ליד "העבר סל" כפתור "נקה N פריטים שלא בשימוש". הלחיצה מבקשת אישור ומסירה אותם מהסל; השורות והמחירים בהן לא משתנים.
- **רשימת מוצרים חסרים מקופלת:** מוצרים שבסל ואינם בנתונים העדכניים מופיעים בשורת כותרת אחת ("N מוצרים שבסל לא נמצאו…") שנפתחת ונסגרת בלחיצה, כדי שלא יידחפו את הטבלה מטה.
- **ייצוא פריטי העיר ל-Excel:** הכפתור "הורד פריטי העיר (Excel)" מוריד קובץ עם כל הפריטים בעיר: ברקוד (כפי שמודפס על האריזה: EAN-8, ‏12 או 13 ספרות, כטקסט כדי לא לאבד ספרות), שם, אריזה, לפי משקל, מספר רשתות, המחיר הזול ביותר ומחיר בכל סניף. אפשר לחפש בקובץ לפי ברקוד. פריטים בלי ברקוד (ירקות ופירות לפי שם) מסומנים. אם ספריית ה-Excel לא נטענת מהרשת, יורד קובץ CSV שנפתח באותו אופן.
- **ערים עם מעט רשתות:** `min_city_chains` ב-`config.json` (כעת 3) קובע שעיר מופיעה באתר רק אם לפחות כל כך הרבה רשתות שונות יש בה סניף. עיר שלא עומדת בכך לא נכתבת ולא מוצגת בבחירת העיר, ובלוג מופיעה שורה `[cities] not listed` עם שמות הערים וכמות הרשתות בכל אחת. רשת שנכשלה בהרצה מסוימת אבל יש לה נתונים קודמים עדיין נספרת, כדי שעיר לא תיעלם ותחזור בין הרצות.
- **קודים שאינם ברקוד:** קוד פנימי של רשת (כמו 7290000000091) יכול לשמש רשת אחת לפלפל אדום ורשת אחרת לדמי משלוח. כשפריט שנמכר לפי משקל מופיע באותו קוד בשמות שאין להם אף מילה משותפת, האיסוף מפצל אותו: כל קבוצת רשתות מקבלת מפתח לפי שם הפריט (כמו מוצר בלי ברקוד), ובלוג מופיעה שורת `[codes]`. בנוסף, `exclude_names` ב-`config.json` (ברירת מחדל "דמי משלוח") מדלג על פריטים שאינם מוצרים.
- **שמות חתוכים:** חלק מהפורטלים חותכים את שם הפריט ב-20 תווים. האיסוף מעדיף שם מלא: אם הרשת פרסמה גם תיאור יצרן שמתחיל בשם החתוך, הוא ישמש כשם; ואם רשת אחרת מציגה את אותו ברקוד בשם ארוך יותר שמתחיל באותו טקסט, השם הארוך יוצג. פריט שרק רשת אחת מוכרת וחתכה את שמו נשאר חתוך, כי המידע לא קיים במקור. בנוסף, אחרי שכל הערים נבנו, שם חתוך מוחלף בשם הארוך ביותר שנראה לאותו ברקוד בכל עיר אחרת (למשל סניף רמי לוי בבני ברק מפרסם את השם המלא ואילו סניפים אחרים חותכים אותו), ובלוג מופיעה שורת `[names]` עם מספר השמות שהושלמו. שם מלא שנלמד נשמר בקובץ `data/names-full.json` ונקרא בהרצה הבאה, כך שהשיפור נשאר גם אם הרצה מסוימת מכסה פחות ערים או סניפים.
- **קבצי מחירים ישנים:** האיסוף בודק את תאריך הקובץ שהפורטל מציג. אם הוא ישן מ-`max_file_age_hours` (ברירת מחדל 36) הוא מבקש רשימה מחדש עד `stale_retries` פעמים (ברירת מחדל 3, בהפרש `stale_retry_wait` שניות), ושומר את החדש ביותר. כך מטופל מצב שבו הפורטל של רשת (למשל אושר עד) מחזיר תצוגה ישנה או חלקית. אם הקובץ נשאר ישן, מופיעה שורת `[fresh]` בלוג, ובכותרת העמודה של הסניף באתר מוצג "נתוני dd.mm".
- **אבחון:** פתיחת האתר עם `?debug=1` בסוף הכתובת מציגה בתחתית הדף יומן קצר של טעינה ושמירת הסל, לצורך איתור תקלות. אין הגבלה על מספר הפריטים בסל.
- **כותרת קפואה:** שורת הרשתות נשארת בראש הטבלה בזמן גלילה, ועמודת המוצרים וסכום הסל נשארים במקומם.
- **סל זול ולא רק פריט זול:** בעמודת החנות עם הסל הזול ביותר מופיע ליד כל פריט כמה הוא יקר יותר מהמחיר הזול ביותר בחנות אחרת. בסיכום מוצג גם מחיר קנייה מפוצלת (הזול בכל שורה, בכמה חנויות).

## הגדרות (`config.json`)

- `chains`: הרשתות לאיסוף, לפי הקוד שלהן בספרייה.
- `cities`: כ-90 ערים. לכל עיר `key` באנגלית, `name` להצגה, `match` עם מילים שמחפשים בעיר או בכתובת של הסניף (הזיהוי מתעלם ממקפים ומגרשיים), ו-`enabled`.
  - עיר עם `"enabled": true` נאספת ומופיעה באתר. ברירת המחדל: 20 הערים הגדולות.
  - כדי להוסיף עיר מהרשימה, משנים את `enabled` ל-`true`. כדי להוסיף עיר שלא ברשימה, מוסיפים שורה חדשה באותו מבנה.
  - כל עיר מוסיפה זמן ריצה (עד 16 קבצי מחירים). אם התהליך ארוך מדי, אפשר להפעיל פחות ערים או להקטין את `stores_per_chain`.
- `stores_per_chain`: כמה סניפים לכל רשת מוצגים כעמודות בטבלה (הסניפים עם הכי הרבה פריטים בקובץ המחירים, כמדד לסניף גדול). ברירת מחדל 1: רק הסניף הגדול, שבדרך כלל גם הזול יותר מסניפי מרכז העיר. פריטים שחסרים בו מושלמים מהסניף הגדול הבא.
- `branches` (לא חובה, בתוך עיר): הצמדת סניף לרשת, למשל `"branches": {"shufersal": "הבושם"}`. הסניף שבכתובת או בשם שלו מופיעה המילה נבחר במקום הסניף הגדול. אם אין התאמה, הלוג כותב שורת `[pin]` והבחירה חוזרת להיות לפי גודל.
- `extra_branches` (לא חובה, בתוך עיר): סניף נוסף לרשת, כעמודה נפרדת בנוסף לסניף הרגיל שלה, למשל `"extra_branches": {"osher-ad": "תרשיש"}`. הזיהוי לפי מילה בכתובת או בשם הסניף, או לפי מספר הסניף בקובץ הרשת עם הקידומת `id:`, למשל `"id:34"`. הצמדה לפי מספר מחפשת בכל סניפי הרשת, גם כשהעיר לא רשומה בקובץ. כך אפשר להצמיד גם ב-`branches`.
- `code` (לא חובה, בתוך עיר): סמל העיר של הלמ"ס (3000 = ירושלים, 5000 = תל אביב ועוד). רמי לוי ואושר עד רושמות בקובץ הסניפים את העיר כקוד מספרי, ולפעמים שם הסניף לא כולל את שם העיר. הקוד מוגדר ב-42 הערים הגדולות, ובנוסף הקוד נלמד אוטומטית מסניפים שזוהו לפי שם. בלוג מופיעה שורה `[codes]` לכל עיר.
- `labels` (לא חובה, בתוך עיר): שם מפורש לעמודת סניף, כשהקובץ של הרשת לא כולל כתובת. המפתח הוא `רשת:מספר סניף`, למשל `"labels": {"osher-ad:9": "אושר עד, היהלומים 9"}`. מספר הסניף מופיע בשורות `[branch]` בלוג.
- `fuzzy_city_match` (ברירת מחדל `true`): כשלרשת אין אף סניף בעיר לפי התאמה מדויקת, הקוד מנסה שוב עם שגיאת כתיב של אות אחת בשמות של חמש אותיות ויותר, ועם קיצורים מוכרים (ראשל"צ, ת"א, פ"ת, ירושלם ועוד). בלוג מופיעה שורה `[match] ... found by spelling variants`.
- `candidate_stores`: כמה סניפים של כל רשת בעיר מורידים בפועל. 0 = כל הסניפים בעיר. ברירת מחדל 6.
- `fill_gaps`: אם `true`, פריט שנמצא בסניף אחר של אותה רשת בעיר ולא בסניפים שמוצגים מתווסף לרשימה, עם המחיר מאותו סניף. כך הרשימה היא האיחוד של כל הסניפים, כל פריט מופיע פעם אחת, והחיפוש רץ עליה.
- `min_chains`: בכמה רשתות לפחות צריך להימצא מוצר עם ברקוד כדי להופיע (1 = כל המוצרים).
- `max_products`: כמה מוצרים עם ברקוד בקטלוג של כל עיר. 0 = בלי הגבלה (ברירת מחדל). הגבלה חותכת מוצרים שנמצאים ברשת אחת, ולכן לא מומלצת.
- `include_unbarcoded`: האם לאסוף גם מוצרים בלי ברקוד, כמו ירקות, פירות ודגים לפי משקל.
- `loose_min_chains`: בכמה רשתות לפחות צריך להופיע שם זהה של מוצר בלי ברקוד (1 = כל המוצרים, גם אם הם נמצאים רק ברשת אחת).
- `max_loose`: כמה מוצרים בלי ברקוד בקטלוג של כל עיר. 0 = בלי הגבלה.
- `watch`: רשימת שמות מוצרים או מספרי קוד לבדיקה. בכל הרצה, בלוג של שלב "איסוף מחירים", מופיעות שורות `[watch]` שאומרות אם המוצר נמצא בקבצי הרשתות, באילו רשתות, והאם נכנס לנתוני האתר. אם לא נכנס, כתוב למה (חתוך בגלל המגבלות, או נמצא בפחות רשתות מדי). אם לא נמצא בכלל, הסניפים שנדגמו כנראה לא מחזיקים אותו, ואפשר להגדיל את `stores_per_chain`.
- בסוף הלוג יש גם `[summary]` עם מצב כל רשת ושגיאה אם נכשלה.

## בעיות ידועות

- חלק מאתרי הרשתות חסומים מחוץ לישראל. שרתי GitHub נמצאים בחו״ל, ולכן רשת שנכשלת מופיעה באתר כ"לא התקבל עדכון", ונשמרים הנתונים הקודמים שלה כ"נתונים ישנים". הפתרון הוא להריץ את התהליך על מחשב בישראל: להתקין [self-hosted runner](https://docs.github.com/en/actions/hosting-your-own-runners) ולהגדיר במאגר משתנה בשם `RUNNER_LABEL` עם התווית שלו.
- בסניפים שבהם העיר לא מופיעה בקובץ הסניפים או בכתובת, הסניף לא יזוהה. כדאי להוסיף מילים ב-`match`.
- מוצרים בלי ברקוד (ירקות, פירות, דגים) מותאמים בין רשתות לפי השם בלבד. בפריטים שנמכרים לפי משקל מוסרים מהשם מספרים ויחידות, ובפריטים באריזה קבועה (למשל 800 גרם) הגודל נשאר חלק מהשם, כדי שלא יתאחדו אריזות שונות. רשת שקוראת למוצר בשם אחר תופיע כשורה נפרדת, ובהשוואה שלה יסומן "אין במלאי" בשאר הרשתות. כברירת מחדל (`loose_min_chains: 1`) מוצגים כל המוצרים, גם אלה שנמצאים רק ברשת אחת. כשיש כמה וריאנטים של אותו שם באותו סניף, נלקח הזול שבהם. בהרצה הראשונה כדאי לבדוק אם החיפוש מוצא את מה שאתה צריך. אם הרשימה ארוכה מדי, אפשר להעלות את `loose_min_chains` ל-2.
- מחירי מבצעים אינם כלולים.
- ב-GitHub, תזמון אוטומטי במאגר ציבורי מושבת אחרי כ-60 יום בלי פעילות במאגר. אפשר להפעיל אותו מחדש בלשונית Actions.

- **עשרה תזמונים עם בדיקת מרווח, וסטטוס:** במקום תזמון אחד כל שעתיים, `update.yml` מכיל 10 תזמונים בדקות שונות (בערך כל 12 דקות במשך שעתיים), כי GitHub מדלג על חלק מההפעלות המתוזמנות ומאחר אחרות. שלב `guard` (הסקריפט `scripts/guard.py`) בודק בתחילת כל ניסיון מתוזמן, לפי היסטוריית ההרצות של GitHub עצמו, מתי התחיל האיסוף האחרון שהצליח או שעדיין רץ: אם עברו פחות מ-105 דקות (`MIN_GAP_MIN` ב-`update.yml`) הניסיון מדלג תוך שניות, ואחרת מתחיל איסוף. איסוף שנכשל לא נחשב, ולכן הניסיון הבא ינסה שוב. אם ה-API של GitHub לא עונה, הבדיקה נשענת על `generated_at` באתר, ואם גם זה נכשל האיסוף רץ. הבדיקה לא ממתינה לאיסוף שרץ (הוא נמצא ב-concurrency נפרד), ולכן ניסיון שמגיע באמצע איסוף מדלג מיד. הפעלה ידנית והעלאת קבצים אף פעם אינן מדולגות. הדף `status.html` מציג לכל הפעלה את זמנה, את סוגה (מתוזמנת / ידנית / העלאת קבצים), את מספר השעות מההפעלה המתוזמנת הקודמת, ולכל רשת כמה קבצים ירדו וכמה נכשלו. ההיסטוריה (80 הפעלות אחרונות) נשמרת ב-`data/index.json`. לכוונון ל-90 דקות (בערך פעם בשעה וחצי) מחליפים את `MIN_GAP_MIN` ל-"90".
